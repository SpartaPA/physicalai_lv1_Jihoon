## 1. 파이프라인 전체 구조

- 좌표계 체인 (base -> link -> camera -> object): base를 원점으로 link(관절), camera(link에 고정), object(카메라 앞 60cm) 순으로 `T_base_link @ T_link_cam @ T_cam_obj` 로 조립한다.
- 각 노트북·모듈이 맡는 역할: 01 파이프라인(좌표계 정의와 camera→base 변환), 02 보간(SLERP와 궤적 생성), 03 자세 추정·시연(PCA/Kabsch와 애니메이션).
- 데이터 흐름: 카메라 점군 -> `PosePipeline` -> base 점군 -> PCA/Kabsch -> 목표 자세 -> SLERP + 스플라인 -> 애니메이션
- 모듈 ③ 에서 가져온 함수와 이번에 새로 만든 함수 구분: 가져온 함수(`rot_*`, `make_T`, `inv_T`, `transform_*`, `CoordinateChain`)와 신규 함수(`PosePipeline`, `quaternion` 4종, `trajectory` 4종, `pca_axes`/`kabsch`/`fit_plane_lstsq`/`remove_outliers`)로 구분된다.

## 3. 노이즈·점 개수가 정확도에 미친 영향

- 노이즈 0 ~ 0.25 스윕에서 오차가 어떻게 커졌는가: 노이즈가 커질수록 세 계열 모두 오차가 커진다 (30개: 0.0 -> 19.7도, 270개: 0.0 -> 8.7도).
- 점 개수 30 / 90 / 270 계열 비교: 고노이즈 구간에서 270개가 30개보다 약 3배 정확하다. 점이 많을수록 평균화로 노이즈가 상쇄된다.
- 구형 점군에서 PCA 주축이 불안정해진 이유 (고유값 관점): 구형은 고유값이 거의 같아(λ1/λ2=1.19) 주축 방향이 노이즈에 흔들리기 때문이다 (흔들림 길쭉 2.48도 vs 구형 72.73도).
- 오차 그래프 (03 노트북 캡처): 위 5-4 그림 참조.

## 4. 현재 구현의 한계

- 자세 추정: 대응이 알려진 경우에만 Kabsch가 동작하고, 대칭 물체에서는 PCA 축 부호가 모호하다.
- 궤적 생성: 충돌·관절 한계를 고려하지 않고 속도·가속도 상한을 반영하지 않는다.
- 파이프라인: 관절 1개로 단순화했고 카메라 캘리브레이션 오차를 무시한다.
- 시연: 정적 장면·개루프 재생이며 외란이나 추적 오차를 다루지 않는다.

## 5. 개선한다면 무엇을 어떻게

- 대응 없는 정합 -> ICP로 대응을 반복 추정한다.
- 평면 피팅 강건화 -> RANSAC으로 이상치에 더 강하게 만든다.
- 궤적 최적화 -> 최소 저크 궤적과 속도·가속도 제한을 반영한다.
- 개선 효과를 어떻게 측정할 것인지: 각도 오차·RMSE·가속도 점프를 노이즈 스윕과 함께 재측정해 전후를 비교한다.
